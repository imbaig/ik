# Music Store AI Constitution

Version: 1.0.0-draft | Prepared: 2026-11-07 | Ratification: pending Imran review

## Core principles

1. **Specification before implementation.** Reconcile the complete course guide, rubric
   and milestones into traceable requirements and acceptance scenarios. Imran reviews
   the spec revision before implementation. Framework adoption is not baseline approval.
2. **Independent agent review and human authority.** A separate read-only reviewer
   examines each milestone revision. Human findings and agent findings adopted by Imran
   cannot be declined, downgraded, deferred or closed by the author alone. Other findings
   may be declined with recorded evidence. Only Imran signs off milestones.
3. **Grounded customer outcomes.** Catalog and account facts come from tools. Identity
   verification precedes private access. Trusted application code enforces customer
   ownership; model-provided identifiers never authorize queries. SQL uses bindings.
4. **Reproducible evidence.** Record artifact revisions/hashes, reviewer identity,
   findings, dispositions, verification and approval. Distinguish deterministic tests,
   fake-model tests and live-model evaluations. Do not invent passes or approvals.
5. **Bounded scope and safe delivery.** Preserve weekly coursework and unrelated changes.
   Keep secrets and confidential course originals out of Git. Deliver the original music
   store capstone by November 20, 2026; extensions require explicit scope decisions.

## Process and artifacts

Use Spec Kit's specify/clarify/plan/tasks/analyze steps before implementation. Retain
existing specs as draft inputs until reconciliation creates an authoritative feature
packet. Do not treat templated guidance or an agent readiness verdict as human approval.
The workflow in docs/development-review-workflow.md defines finding decision rights.

## Governance

Changes affecting agreed scope, mandatory findings or approval gates require Imran's
review. Course/source conflicts must be explicit. This draft records established user
instructions; it does not claim ratification of the technical specification.
